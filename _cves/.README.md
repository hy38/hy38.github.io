# CVE Writeup Authoring

Publish only CVEs found by Sanghyun Park in this collection.

## File path

Use this pattern:

```text
_cves/cve-yyyy-nnnn-short-target.md
```

Files in this collection publish under `/cves/:path/` when `published` is not `false`.

## Required front matter

```yaml
---
layout: single
title: "CVE-YYYY-NNNN Target Finding"
description: "Short public summary of the finding."
date: 2026-01-01
cve: "CVE-YYYY-NNNN"
target: "Kernel"
product: "Affected project or component"
found_by_me: true
status: "published"
severity: "TBD"
cvss_version: "TBD"
cvss_score: "TBD"
cvss_severity: "TBD"
cvss_source: "TBD"
cvss_vector: "TBD"
toc: true
references:
  - "https://example.com/advisory"
tags:
  - cve
---
```

Use `found_by_me: true` only for CVEs you personally found. Thesis reproduction notes, literature analysis, and researched third-party CVEs belong in `_research/` or `_posts/`, not here.

Use the CVSS fields only after a public CNA, NVD, vendor advisory, or equivalent record publishes the score and vector. Leave them as `TBD` until then.

Each public writeup should include an `Exploit` section after `Fix` and before `Timeline`. Use it to summarize exploit attempts, validation status, and practical blockers. Do not publish private reproducer code, exploit code, or instructions that are not approved for public release.

Do not commit private disclosure details, embargoed information, private correspondence, or proof-of-concept code that is not approved for public release.
